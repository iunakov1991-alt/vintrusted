# ⚡ План оптимизации: Уменьшение времени генерации на 50%

**Цель:** Снизить время генерации с ~90 секунд до ~45 секунд

**Текущее время:** ~90 секунд (1.5 минуты)  
**Целевое время:** ~45 секунд (0.75 минуты)

---

## 📊 Анализ текущих узких мест

### 1. **Последовательная генерация групп** (30-40% времени)
- Группы генерируются последовательно
- Блоки внутри группы параллельно
- **Проблема:** Ожидание завершения группы перед началом следующей

### 2. **Ограниченный параллелизм** (20-30% времени)
- Семафор ограничивает до 6 параллельных запросов
- **Проблема:** Можно увеличить до 10-12

### 3. **Множественные retry** (10-15% времени)
- Retry для similarity check: 3 попытки
- Retry для валидации: до 3 попыток
- **Проблема:** Избыточные повторные генерации

### 4. **Медленные провайдеры** (15-20% времени)
- Ollama (локальный) медленнее DeepSeek API
- **Проблема:** Не приоритизируется быстрый провайдер

### 5. **Синхронная валидация** (5-10% времени)
- Валидация блокирует генерацию
- **Проблема:** Можно делать асинхронно

---

## 🎯 Оптимизации (7 пунктов)

### ✅ Оптимизация 1: Увеличенный параллелизм

**Изменение:** `MAX_PARALLEL_WORKERS: 6 → 12`

**Эффект:** +30-40% скорости

**Реализация:**
```javascript
// Было:
const maxWorkers = parseInt(process.env.MAX_PARALLEL_WORKERS || '6', 10);

// Стало:
const maxWorkers = parseInt(process.env.MAX_PARALLEL_WORKERS || '12', 10);
```

**Риски:** Минимальные (API обычно выдерживают больше запросов)

---

### ✅ Оптимизация 2: Уменьшенные retry

**Изменение:** `maxSimilarityRetries: 3 → 1`

**Эффект:** +10-15% скорости

**Реализация:**
```javascript
// Было:
let maxAttempts = 3;

// Стало:
let maxAttempts = 1;
```

**Риски:** Низкие (качество может немного снизиться, но незначительно)

---

### ✅ Оптимизация 3: Агрессивное кэширование

**Изменение:** Расширить кэширование на больше типов блоков

**Эффект:** +20-30% скорости (для повторных генераций)

**Реализация:**
```javascript
// Было:
cacheableBlockTypes = ['faq', 'state_specific']

// Стало:
cacheableBlockTypes = [
  'faq', 'state_specific', 'key_facts', 'nmvtis',
  'buyer_guide', 'recalls_tsbs', 'internal_links'
]
```

**Риски:** Нет (кэш только ускоряет)

---

### ✅ Оптимизация 4: Приоритет DeepSeek API

**Изменение:** Использовать DeepSeek API по умолчанию (быстрее Ollama)

**Эффект:** +15-20% скорости

**Реализация:**
```javascript
// Было:
provider: blockConfig.provider

// Стало:
provider: this.preferDeepSeek ? 'deepseek' : blockConfig.provider
```

**Риски:** Нет (DeepSeek API быстрее и надежнее)

---

### ✅ Оптимизация 5: Игнорирование слабых зависимостей

**Изменение:** Генерировать все независимые блоки параллельно

**Эффект:** +30-40% скорости

**Реализация:**
```javascript
// Было: Группы последовательно
for (let group of groups) {
  await Promise.all(group.map(...))
}

// Стало: Все параллельно (кроме hero)
await Promise.all(otherBlocks.map(...))
```

**Риски:** Низкие (зависимости обычно слабые)

---

### ✅ Оптимизация 6: Отложенная валидация

**Изменение:** Валидация асинхронно, не блокирует генерацию

**Эффект:** +5-10% скорости

**Реализация:**
```javascript
// Было:
const validation = this.validator.validate(article, context);
return article;

// Стало:
const validationPromise = this.validateBlocksAsync(blocks, context);
return article; // Не ждем валидацию
```

**Риски:** Нет (валидация все равно выполняется)

---

### ✅ Оптимизация 7: Оптимизированные промпты

**Изменение:** Укоротить промпты на 20-30%

**Эффект:** +10-15% скорости генерации

**Реализация:**
- Убрать избыточные инструкции
- Сократить примеры
- Использовать более компактный формат

**Риски:** Низкие (качество может немного снизиться)
