## 🔍 КАК ЭТО РАБОТАЕТ СЕЙЧАС

### Текущая логика:

1. **Во время выполнения партии:**
   - `build_topics_batch_parallel.js` обновляет `tmp/batch-status.json` локально в GitHub Actions runner
   - Статус обновляется после каждой батча страниц (строка 233)
   - **НО:** Этот статус НЕ отправляется на Vercel во время выполнения

2. **В конце выполнения:**
   - GitHub Actions шаг "Update batch status via API" (строка 146)
   - Выполняется с `if: always()` - даже если партия упала
   - Читает финальный статус из `tmp/batch-status.json`
   - Отправляет POST на `/api/batch-status` → сохраняет в Upstash Redis

## ⏰ КОГДА ОБНОВИТСЯ

**Статус обновится:**
- ✅ **После завершения партии** (когда GitHub Actions workflow завершится)
- ❌ **НЕ обновляется во время выполнения** (только в конце)
