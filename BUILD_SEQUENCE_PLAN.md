## ✅ ЭТАП 1: ДО ПЕРВОГО БИЛДА (Критично для генерации)

### 1.1 AI Seed Expansion (Приоритет #1)
**Почему ДО:**
- Определяет, какие страницы генерировать
- Влияет на seed-list для URL Factory
- Оптимизирует покрытие с первого билда
- **AI определяет оптимальный объем билда** на основе анализа эффективности

**Модули:**
- `scripts/seo/seeds/seed-analyzer.js`
- `scripts/seo/seeds/seed-generator.js`
- `scripts/seo/seeds/seed-expansion-engine.js`

**AI Логика определения объемов:**
- Анализ предыдущих билдов (количество страниц, качество, метрики)
- Анализ ограничений (Groq лимиты: 150-200 страниц/день)
- Анализ эффективности (какие объемы дали лучшие результаты)
- Анализ пробелов в покрытии (сколько нужно для заполнения)
- Анализ ресурсов (доступные API лимиты, кеш)
- **Рекомендация оптимального объема** для максимальной эффективности

**Выходные данные:**
```json
{
  "recommended_build_volume": 500,  // AI определяет оптимальный объем
  "reasoning": "Анализ показал, что 500 страниц оптимально для текущих лимитов Groq и пробелов в покрытии...",
  "expanded_seed_list": { ... },
  "build_strategy": {
    "groq_pages": 150,      // Сколько через Groq
    "deepseek_pages": 350,  // Сколько через DeepSeek
    "cached_pages": 0,      // Сколько из кеша
    "priority_order": ["high_traffic", "missing_coverage", "quality_boost"]
  }
}
```

**Интеграция:**
- Этап 0.3 в pipeline (перед ai-decision)
- Обновление `urlFactory.updateSeeds()`
- Обновление `config.targetPagesPerBuild` с AI рекомендацией

## ✅ ЭТАП 2: СРАЗУ ПОСЛЕ ПЕРВОГО БИЛДА (Улучшение существующих страниц)

**Почему ПОСЛЕ:**

### 2.2 Tier-based Canonical Logic (Приоритет #2)
**Почему ПОСЛЕ:**
- Анализирует уже созданные страницы

**Модуль:**
- `scripts/seo/links/canonical-engine.js`

**Интеграция:**
