# 🚀 СТРАТЕГИЯ ДЕПЛОЯ MONSTER 8.0

## 📋 ОБЗОР

MONSTER 8.0 генерирует статические HTML страницы в `public/semantic-pages/` с структурой:
```
public/semantic-pages/
├── en/
│   └── dmv-titles/
│       └── {state}/
│           └── title-types/
│               └── checklist/
│                   └── index.html
└── es/
    └── ...
```

URL структура: `https://vintrusted.com/en/...` или `https://vintrusted.com/es/...`

---

## 🛡️ ПРЕДОТВРАЩЕНИЕ 404

### 1. **Валидация перед деплоем**
```bash
node scripts/validate_before_deploy.js
```

**Проверяет:**
- ✅ Наличие всех файлов
- ✅ Валидность HTML
- ✅ Минимальный размер файлов
- ✅ Наличие обязательных элементов (title, h1)

**Блокирует деплой** если найдены ошибки.

---

### 2. **Vercel Rewrites**
```json
{
  "source": "/en/(.*)",
  "destination": "/api/semantic-page.js?lang=en&path=$1"
},
{
  "source": "/es/(.*)",
  "destination": "/api/semantic-page.js?lang=es&path=$1"
}
```

**Как работает:**
1. Запрос: `https://vintrusted.com/en/dmv-titles/ca/title-types/checklist/`
2. Vercel ищет статический файл: `public/semantic-pages/en/dmv-titles/ca/title-types/checklist/index.html`
3. Если найден → отдает статический файл
4. Если не найден → перенаправляет на `/api/semantic-page.js` (fallback)

---

### 3. **API Fallback (`api/semantic-page.js`)**
**Назначение:** Обработка запросов к несуществующим страницам

**Логика:**
1. Проверяет существование файла в `public/semantic-pages/{lang}/{path}/index.html`
2. Если найден → отдает HTML
3. Если не найден → возвращает 404 с понятным сообщением

**Преимущества:**
- Нет массовых 404 при частичном деплое
- Понятные сообщения об ошибках
- Возможность логирования отсутствующих страниц

## ⚠️ ВАЖНЫЕ ЗАМЕЧАНИЯ

### 1. **Порядок Rewrites**
Rewrites в `vercel.json` обрабатываются **сверху вниз**. Важно:
- Специфичные правила (`/en/*`, `/es/*`) должны быть **перед** общими
- API routes должны быть в конце

### 2. **Кэширование**
- Статические файлы: `Cache-Control: public, max-age=3600`
- При обновлении страницы нужно инвалидировать кэш
- Vercel автоматически обновляет при новом деплое

### 3. **Sitemap**
- Генерируется автоматически
- Обновляется при каждом деплое
- Содержит только существующие страницы
