**Дата:** 2025-12-06  
**Конфигурация:** `config/batch-strategy.json`

---

## 🎯 ЧТО ТАКОЕ АДАПТИВНАЯ СТРАТЕГИЯ?

**Адаптивная стратегия** = размер партии **автоматически меняется** в зависимости от того, **сколько времени прошло** с последней партии.

---

## 📋 КАК РАБОТАЕТ

### Основной принцип:

Система смотрит: **"Сколько часов прошло с последней партии?"**

И в зависимости от ответа выбирает размер:

| Время с последней партии | Размер партии | Пример (maxPagesPerBatch = 100) |
|-------------------------|---------------|--------------------------------|
| **< 12 часов** | **50%** от максимума | **50 страниц** |
| **12-24 часа** | **75%** от максимума | **75 страниц** |
| **≥ 24 часа** | **100%** от максимума | **100 страниц** |

---

## 🔍 ДЕТАЛЬНАЯ ЛОГИКА

### Код из `scripts/batch_scheduler.js`:

```javascript
function calculateNextBatchParams(lastBatch, strategy) {
  const now = new Date();
  const lastBatchTime = lastBatch ? new Date(lastBatch.completedAt) : new Date(now.getTime() - 24 * 60 * 60 * 1000);
  
  // Вычисляем интервал с момента последней партии
  const hoursSinceLastBatch = (now - lastBatchTime) / (1000 * 60 * 60);
  
  // Определяем размер партии
  let batchSize = strategy.maxPagesPerBatch; // По умолчанию = 100
  
  if (strategy.batchSizeStrategy === 'adaptive') {
    // Адаптивный размер на основе времени с последней партии
    if (hoursSinceLastBatch < 12) {
      batchSize = Math.floor(strategy.maxPagesPerBatch * 0.5);  // 50 страниц
    } else if (hoursSinceLastBatch < 24) {
      batchSize = Math.floor(strategy.maxPagesPerBatch * 0.75); // 75 страниц
    }
    // Если >= 24 часов, остается 100 страниц (максимум)
  }
  
  return { batchSize, ... };
}
```

## 📊 ПРИМЕРЫ РАБОТЫ

### Пример 1: Частые партии

**Сценарий:** Партии запускаются каждые 6 часов

```
Партия 1: 100 страниц (первая партия, прошло > 24 часов)
  ↓ (через 6 часов)
Партия 2: 50 страниц (прошло < 12 часов)
  ↓ (через 6 часов)
Партия 3: 50 страниц (прошло < 12 часов)
  ↓ (через 6 часов)
Партия 4: 50 страниц (прошло < 12 часов)
```

**Результат:** Система **снижает нагрузку**, если партии идут слишком часто.

---

### Пример 2: Редкие партии

**Сценарий:** Партии запускаются раз в сутки

```
Партия 1: 100 страниц (первая партия)
  ↓ (через 24 часа)
Партия 2: 100 страниц (прошло ≥ 24 часов)
  ↓ (через 24 часа)
Партия 3: 100 страниц (прошло ≥ 24 часов)
```

**Результат:** Система использует **полный размер**, так как есть время на обработку.

---

### Пример 3: Средняя частота

**Сценарий:** Партии запускаются каждые 18 часов

```
Партия 1: 100 страниц (первая партия)
  ↓ (через 18 часов)
Партия 2: 75 страниц (прошло 12-24 часа)
  ↓ (через 18 часов)
Партия 3: 75 страниц (прошло 12-24 часа)
```

**Результат:** Система использует **средний размер**, балансируя нагрузку.

## ✅ ПРЕИМУЩЕСТВА АДАПТИВНОЙ СТРАТЕГИИ

### 1. **Защита от перегрузки**
- Если партии идут слишком часто → размер уменьшается
- Предотвращает перегрузку системы и API

### 2. **Максимальная эффективность**
- Если партии идут редко → размер максимальный
- Использует доступное время для генерации большего объема

### 3. **Автоматическая балансировка**
- Не нужно вручную менять размер батча
- Система сама адаптируется к частоте запусков

### 4. **Предсказуемость**
- Четкие правила: < 12ч = 50%, 12-24ч = 75%, ≥ 24ч = 100%
- Легко понять, какой размер будет в следующей партии

## ⚙️ КОНФИГУРАЦИЯ

### Текущие настройки (`config/batch-strategy.json`):

```json
{
  "minIntervalHours": 24,        // Минимальный интервал между партиями
  "maxPagesPerBatch": 100,        // Максимальный размер партии
  "preferredTimes": ["09:00", "15:00", "21:00"], // Предпочтительное время
  "batchSizeStrategy": "adaptive", // Стратегия: adaptive
  "workingDaysOnly": false,       // Работает и в выходные
  "timezone": "America/New_York"  // Часовой пояс
}
```

### Как изменить:

1. **Изменить максимальный размер:**
   ```json
   "maxPagesPerBatch": 200  // Вместо 100
   ```
   Тогда: 50% = 100, 75% = 150, 100% = 200

2. **Изменить пороги времени:**
   Нужно изменить код в `scripts/batch_scheduler.js`:
   ```javascript
   if (hoursSinceLastBatch < 6) {      // Вместо 12
     batchSize = Math.floor(strategy.maxPagesPerBatch * 0.5);
   } else if (hoursSinceLastBatch < 18) { // Вместо 24
     batchSize = Math.floor(strategy.maxPagesPerBatch * 0.75);
   }
   ```

3. **Использовать другую стратегию:**
   ```json
   "batchSizeStrategy": "fixed"      // Всегда 100 страниц
   "batchSizeStrategy": "progressive" // Прогрессивное увеличение
   ```

## 🔄 АЛЬТЕРНАТИВНЫЕ СТРАТЕГИИ

### 1. **Fixed (Фиксированная)**
```javascript
batchSize = strategy.maxPagesPerBatch; // Всегда 100
```
- ✅ Простота
- ❌ Не адаптируется к частоте

### 2. **Progressive (Прогрессивная)**
```javascript
const batchNumber = lastBatch ? lastBatch.batchNumber + 1 : 1;
batchSize = Math.min(strategy.maxPagesPerBatch, 20 + (batchNumber * 10));
// Партия 1: 30 страниц
// Партия 2: 40 страниц
// Партия 3: 50 страниц
// ...
// Партия 8: 100 страниц (максимум)
```
- ✅ Постепенное увеличение
- ❌ Не учитывает время между партиями

### 3. **Adaptive (Адаптивная)** ← **ТЕКУЩАЯ**
- ✅ Учитывает время между партиями
- ✅ Автоматическая балансировка
- ✅ Защита от перегрузки

## ✅ ЗАКЛЮЧЕНИЕ

**Адаптивная стратегия** автоматически подстраивает размер партии под частоту запусков:

- **Частые партии** (< 12ч) → **Меньший размер** (50%) → Защита от перегрузки
- **Средние партии** (12-24ч) → **Средний размер** (75%) → Баланс
- **Редкие партии** (≥ 24ч) → **Максимальный размер** (100%) → Максимальная эффективность

**Результат:** Система работает оптимально при любой частоте запусков! 🎯
