# Технические ограничения и пределы работоспособности

## 🚀 Vercel Pro Plan - Лимиты

### Build Limits
- **Максимальное время билда**: 45 минут (2700 секунд)
- **Максимальный размер билда**: 100 GB
- **Максимальное количество функций**: 1000 serverless functions
- **Concurrent builds**: До 10 одновременных билдов

### Runtime Limits
- **Memory per function**: До 3 GB
- **Execution time per function**: До 60 секунд (Hobby) / 300 секунд (Pro)
- **Request body size**: 4.5 MB (API routes)
- **Response size**: 4.5 MB (API routes)

## 📊 SEO Monster 3.0 - Текущие настройки

### Конфигурация (`data/seo/config.json`)
```json
{
  "targetPagesPerBuild": 15000,
  "maxPagesPerCluster": 500,
  "minQualityScore": 0.7,
  "enableAI": true,
  "aiMaxTokens": 600
}
```

### Переменные окружения
- `SEO_BUILD_CONCURRENCY`: 8 (по умолчанию), можно увеличить до 12-16
- `SEO_ENABLE_AI`: 1 (включено)
- `GROQ_API_KEY`: требуется для AI
- `DEEPSEEK_API_KEY`: fallback для AI

## ⚠️ Практические ограничения

### 1. Количество страниц за билд

**Теоретический максимум**: 15000 страниц (настроено в config.json)

**Практический максимум**:
- **С AI**: ~10,000-12,000 страниц (зависит от скорости API)
- **Без AI**: ~15,000 страниц (быстрее, но хуже контент)

**Рекомендация**: 
- Для стабильности: 8,000-10,000 страниц
- Для максимальной скорости: 5,000-8,000 страниц

### 2. Время билда

**Оценка времени**:
- 1000 страниц: ~30-60 секунд
- 5000 страниц: ~2-4 минуты
- 10000 страниц: ~5-10 минут
- 15000 страниц: ~10-20 минут

**Факторы влияния**:
- Скорость AI API (Groq/DeepSeek)
- Количество параллельных запросов (`SEO_BUILD_CONCURRENCY`)
- Размер кеша AI (меньше запросов = быстрее)

### 3. Память (Memory)

**Использование памяти**:
- Базовое: ~200-300 MB
- На 1000 страниц: +50-100 MB
- На 10000 страниц: +500-1000 MB
- На 15000 страниц: ~1.5-2 GB

**Лимит Vercel Pro**: 8 GB на билд-машине

**Риск**: При 15000+ страницах может быть нехватка памяти

### 4. Конкурентность (Concurrency)

**Текущая настройка**: 8 параллельных задач

**Рекомендации**:
- **4-6**: Безопасно, но медленно
- **8-10**: Оптимально для большинства случаев
- **12-16**: Быстро, но выше риск ошибок памяти
- **20+**: Не рекомендуется (риск перегрузки)

**Формула**: `concurrency = min(cores * 2, 16)`

### 5. AI API Limits

**Groq API**:
- Rate limit: Зависит от плана (обычно 30-60 req/min)
- Timeout: 30 секунд на запрос
- Fallback: DeepSeek автоматически

**DeepSeek API**:
- Rate limit: Зависит от плана
- Timeout: 30 секунд на запрос

**Стратегия**:
- Кеширование: Все запросы кешируются в `data/seo/ai-cache.jsonl`
- Повторные билды: Используют кеш, не делают новых запросов
- Fallback: Если AI недоступен → используется шаблонный текст

### 6. Размер файлов

**Каждая страница**: ~15-25 KB HTML

**Общий размер**:
- 1000 страниц: ~15-25 MB
- 5000 страниц: ~75-125 MB
- 10000 страниц: ~150-250 MB
- 15000 страниц: ~225-375 MB

**Лимит Vercel**: 100 GB на проект (не проблема)

### 7. Sitemap Limits

**Текущая настройка**: 20,000 URL на файл

**Максимум Google**: 50,000 URL на sitemap

**Наша конфигурация**: Безопасно для любого количества страниц

## 🔧 Оптимизация производительности

### 1. Увеличить конкурентность
```bash
SEO_BUILD_CONCURRENCY=12
```
**Плюсы**: Быстрее билд
**Минусы**: Больше нагрузка на память и API

### 2. Отключить AI для тестов
```bash
SEO_ENABLE_AI=0
```
**Плюсы**: Очень быстро (только шаблоны)
**Минусы**: Нет уникального контента

### 3. Уменьшить количество страниц
```json
{
  "targetPagesPerBuild": 8000
}
```
**Плюсы**: Стабильнее, быстрее
**Минусы**: Меньше страниц

### 4. Увеличить размер кластера
```json
{
  "maxPagesPerCluster": 600
}
```
**Плюсы**: Больше internal links
**Минусы**: Больше нагрузка на память

## 🚨 Критические точки отказа

### 1. Timeout билда
**Когда**: Билд > 45 минут
**Решение**: Уменьшить `targetPagesPerBuild` или `SEO_BUILD_CONCURRENCY`

### 2. Нехватка памяти
**Когда**: Использование > 6-7 GB
**Решение**: Уменьшить `SEO_BUILD_CONCURRENCY` или количество страниц

### 3. Rate limit AI API
**Когда**: Слишком много запросов к Groq/DeepSeek
**Решение**: Увеличить кеш, уменьшить конкурентность, использовать fallback

### 4. Слишком большой sitemap
**Когда**: > 50,000 URL в одном файле
**Решение**: Автоматически разбивается на части (20,000 на файл)

## 📈 Мониторинг
