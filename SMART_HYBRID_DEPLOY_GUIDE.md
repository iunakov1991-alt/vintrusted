# 🚀 Smart Hybrid Deploy — Руководство

**Дата:** 2025-12-10  
**Версия:** 1.0

---

## 📋 Что это?

**Smart Hybrid Deploy** — умная система инкрементальных деплоев, которая автоматически деплоит страницы по мере их генерации, ускоряя попадание контента в индекс Google.

### Преимущества:

✅ **Быстрее в индекс:** Первые страницы попадают на production через 8-15 минут вместо 45  
✅ **Безопаснее:** Если деплой упадёт — не потеряем все страницы  
✅ **Умная логика:** Деплоит только когда нужно, не перегружает систему  
✅ **Гибкость:** 3 стратегии на выбор

---

## 🎯 Стратегии деплоя

### 1. Batch Deploy (по умолчанию для маленьких батчей)

**Как работает:**
```
Генерация: [████████████████████████████████] 30 страниц (45 мин)
                                                    ↓
Деплой:    [████████] 1 деплой (40 сек)
```

**Характеристики:**
- ⏱️ Время до первой страницы: **45 минут**
- 🚀 Деплоев: **1**
- 💰 Стоимость: **$0**
- 📊 Сложность: **Простая**

**Когда использовать:**
- Маленькие батчи (< 50 страниц)
- Тестирование
- Быстрые правки

---

### 2. Smart Hybrid Deploy (рекомендуется) ⭐

**Как работает:**
```
Генерация: [█████-----] 10 страниц (15 мин)
                ↓
Деплой 1:  [██] (40 сек)

Генерация: [█████-----] 10 страниц (15 мин)
                ↓
Деплой 2:  [██] (40 сек)

Генерация: [█████-----] 10 страниц (15 мин)
                ↓
Деплой 3:  [██] (40 сек)
```

**Характеристики:**
- ⏱️ Время до первой страницы: **15 минут** (3x быстрее!)
- 🚀 Деплоев: **3** (каждые 10 страниц)
- 💰 Стоимость: **$0**
- 📊 Сложность: **Средняя**

**Умная логика:**
- Деплоит каждые N страниц ИЛИ каждые M минут
- Пропускает деплой если батч почти завершён (< 5 минут)
- Проверяет наличие изменений перед деплоем
- Автоматически подстраивается под размер батча

**Когда использовать:**
- Средние батчи (50-200 страниц)
- Большие батчи (> 200 страниц)
- Production генерация
- **Рекомендуется для Phase 1-5**

---

### 3. Incremental Deploy (максимальная скорость)

**Как работает:**
```
Каждая страница → Деплой
```

**Характеристики:**
- ⏱️ Время до первой страницы: **8 минут** (5.6x быстрее!)
- 🚀 Деплоев: **30** (каждая страница)
- 💰 Стоимость: **$0** (но близко к лимитам)
- 📊 Сложность: **Высокая**

**Когда использовать:**
- Критически важный контент
- Тестирование деплоя
- Очень маленькие батчи (< 10 страниц)

**⚠️ Внимание:** Может перегрузить Vercel при больших батчах!

## 🛠️ Использование

### Через Dashboard UI

1. Откройте dashboard: `http://localhost:3030/local-batch-dashboard.html`
2. В секции **Controls** выберите **Deploy Strategy**:
   - `Batch` — один деплой в конце
   - `Smart Hybrid` — умная логика (рекомендуется)
   - `Incremental` — каждая страница
3. Если выбрали Smart/Incremental, настройте параметры:
   - **Every N pages:** Деплоить каждые N страниц (по умолчанию: 10)
   - **Or every N minutes:** Или каждые N минут (по умолчанию: 15)
   - **Min remaining time:** Не деплоить если осталось < N минут (по умолчанию: 5)
4. Нажмите **START**

### Через Environment Variables

```bash
# Стратегия деплоя
export DEPLOY_STRATEGY="smart"  # batch, smart, incremental

# Параметры Smart/Incremental
export DEPLOY_EVERY_PAGES="10"
export DEPLOY_EVERY_MINUTES="15"
export DEPLOY_MIN_REMAINING_TIME="5"

# Запуск
npm run monster:dashboard:local
```

### Через API

```bash
curl -X POST http://localhost:3030/api/local-start \
  -H "Content-Type: application/json" \
  -d '{
    "phase": "auto",
    "length": "auto",
    "deployStrategy": "smart",
    "deployEveryPages": 10,
    "deployEveryMinutes": 15,
    "deployMinRemainingTime": 5
  }'
```

### Для разных размеров батчей:

```
┌─────────────────┬──────────────┬───────────────┬──────────────┐
│ Размер батча    │ Стратегия    │ Every Pages   │ Every Minutes│
├─────────────────┼──────────────┼───────────────┼──────────────┤

└─────────────────┴──────────────┴───────────────┴──────────────┘
```

### Для разных фаз:

```
PHASE 1 (0-5k):      smart, every 20 pages
PHASE 2 (5k-20k):    smart, every 30 pages
PHASE 3 (20k-200k):  smart, every 50 pages
PHASE 4 (200k-400k): smart, every 50 pages
PHASE 5 (400k+):     smart, every 50 pages
```

## 🐛 Troubleshooting

### Проблема: Деплой не запускается

**Решение:**
1. Проверьте что `DEPLOY_STRATEGY` не равен `batch`
2. Проверьте что `DEPLOY_ENABLED` не равен `false`
3. Проверьте логи: `tail -f logs/local_batch_*.log`

### Проблема: Слишком много деплоев

**Решение:**
1. Увеличьте `DEPLOY_EVERY_PAGES` (например, с 10 до 20)
2. Увеличьте `DEPLOY_EVERY_MINUTES` (например, с 15 до 30)
3. Или переключитесь на `batch` стратегию

### Проблема: Деплой падает с ошибкой

**Решение:**
1. Проверьте что `vercel` CLI установлен: `vercel --version`
2. Проверьте что вы залогинены: `vercel whoami`
3. Проверьте логи деплоя: `cat logs/deploy_*.log`

## 📚 Архитектура

### Компоненты:

1. **`scripts/smart-deploy-manager.js`**
   - Класс `SmartDeployManager`
   - Логика определения необходимости деплоя
   - Проверка изменений в Git
   - Отправка запросов на деплой

2. **`scripts/build_topics_batch_parallel.js`**
   - Интеграция `SmartDeployManager`
   - Уведомление о завершении страниц
   - Вызов `checkAndDeploy()` после каждого батча
   - Финальный деплой в конце

3. **`scripts/monster8_local_dashboard_server.js`**
   - API `/api/local-deploy` с поддержкой `type: incremental`
   - Передача параметров деплоя через env vars
   - Логирование инкрементальных деплоев

4. **`public/local-batch-dashboard.html`**
   - UI для выбора стратегии
   - Настройка параметров
   - Отображение статистики деплоев

### Поток данных:

```
User (Dashboard UI)
  ↓ (select strategy)
POST /api/local-start
  ↓ (spawn with env vars)
build_topics_batch_parallel.js
  ↓ (initialize)
SmartDeployManager
  ↓ (on page completed)
checkAndDeploy()
  ↓ (if needed)
POST /api/local-deploy (type: incremental)
  ↓
Vercel CLI deploy
  ↓
Update batch state
```
