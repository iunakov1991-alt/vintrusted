# MONSTER 7.x — Реализация системы анти-дубликатов

## ✅ Реализованные компоненты

### 1. 40+ структурных схем (`data/seo/templates/structure_schemes.json`)
- Расширено с 5 до 40+ уникальных порядков блоков
- Каждая страница получает случайную схему из файла
- Примеры: `analytic_tx`, `technical_first`, `legal_then_tech`, `risk_focused`, и т.д.

### 2. 6 стилевых режимов (`data/seo/templates/style_modes.json`)
- Расширено с 4 до 6 режимов:
  - `legal_academic` — формальный академический стиль
  - `forensic_engineer` — инженерно-форензический стиль
  - `consumer_practical` — практичный потребительский стиль
  - `investigative` — расследовательский стиль
  - `market_economics` — экономико-рыночный стиль
  - `procedural` — процедурный DMV стиль

### 3. Система глубины блоков S/M/L (`data/seo/templates/block_depth.json`)
- Каждый блок получает случайный уровень глубины:
  - **S (Small)** — 30% вероятность
  - **M (Medium)** — 50% вероятность
  - **L (Large)** — 20% вероятность
- Разброс ±10% для естественной вариативности

### 4. VIN specs база данных (`data/seo/templates/vin_specs.json`)
- Точные спецификации для каждой модели/года
- Включает: WMI, engine codes, safety systems, assembly plants, VIN position breakdowns
- Используется для генерации точных VIN декодеров без ошибок

### 5. State-specific intelligence (`data/seo/templates/state_risks.json`)
- Расширенные данные по штатам:
  - Риски (hail belt, flood incidents, theft corridors)
  - Законы (Transportation Code, DMV regulations)
  - Практики (inspections, documentation)
  - Паттерны мошенничества
- Случайный выбор 2-4 рисков для каждого блока

### 6. Анти-шаблонные промпты (`data/seo/templates/antishablon_prompt.txt`)
- Инструкции для LLM по избежанию повторений
- Проверка схожести с предыдущими блоками
- Вариация структуры предложений, переходов, форматов

### 7. TRIZ-анти-обрывы (`data/seo/templates/triz_anti_cutoff.txt`)
- Строгие требования к завершению блоков
- Запрет на обрывы с "to", "for", "with", "including"
- Гарантия полных грамматически правильных предложений

### 8. Рекомбинация форматов блоков (`data/seo/templates/block_variants.json`)
- Варианты форматов для каждого типа блока:
  - `vin_decoder`: table, bullet_list, dense_text, structured_sections
  - `accident_intelligence`: bullets, case_study, narrative, risk_matrix
  - `buyer_guide`: steps, questions, risks_list, checklist
  - И т.д.

### 9. FACT-LOCK CORE — Ядро точности (`data/facts/`)
- **Эталонные справочники:**
  - `vehicles.json` — точные спецификации марок/моделей/лет (WMI, двигатели, платформы)
  - `states.json` — точные данные по штатам (title systems, агентства, статуты, бренды)
  - `global_invariants.json` — глобальные инварианты (длина VIN, запрещенные утверждения)
- **FACT-SHEET генерация:**
  - Скрипт `scripts/build_factsheet.js` создает строгий JSON-факт-лист для каждой страницы
  - FACT-SHEET валидируется перед генерацией (VIN длина, наличие модели/штата)
  - Сохраняется в `data/factsheets/<VIN>.json` для повторного использования
- **Промпт-контракт:**
  - `data/seo/templates/factlock_prompt_header.txt` — жёсткие правила для LLM
  - LLM получает FACT-SHEET JSON и инструкции использовать ТОЛЬКО факты из него
  - Запрет на изобретение engine codes, WMI, state laws, title systems

## 🚀 Использование

Система работает автоматически при генерации статей. Все шаблоны загружаются из файлов в `data/seo/templates/` при инициализации `ArticleVariationEngine`.

Для добавления новых схем/режимов/спецификаций — просто редактируйте соответствующие JSON файлы.

### FACT-LOCK CORE

**Автоматическая работа:**
- При генерации статьи система автоматически строит/загружает FACT-SHEET
- FACT-SHEET добавляется в начало каждого промпта блока
- LLM получает строгие инструкции использовать только факты из FACT-SHEET

**Ручная генерация FACT-SHEET:**
```bash
node scripts/build_factsheet.js "<VIN>" "<Make> <Model>" <Year> <State>
# Пример:
node scripts/build_factsheet.js "19UUB2F50KA123456" "Honda Accord" "2019" "Texas"
```

**Добавление новых данных:**
- Новые модели: редактируйте `data/facts/vehicles.json`
- Новые штаты: редактируйте `data/facts/states.json`
- Новые инварианты: редактируйте `data/facts/global_invariants.json`

**Важно:** 
- Если модель/штат отсутствует в справочниках, система использует **fallback режим** с декодированием VIN и общими правилами
- FACT-SHEET всегда создается, но помечается как `fallback_vin_decode` если данных нет в базе
- Качество генерации остается высоким независимо от наличия данных в базе

## 🎯 Универсальность и качество

### Универсальная работа с любыми марками/моделями/штатами

Система FACT-LOCK работает универсально для **любых** комбинаций марка/год/штат:

1. **Если данные есть в базе** (`vehicles.json`, `states.json`):
   - Используются точные спецификации
   - FACT-SHEET помечается как `source: 'database'`

2. **Если данных нет в базе** (fallback режим):
   - Используется декодирование VIN для определения WMI, производителя, типа
   - Используются общие правила для штата
   - FACT-SHEET помечается как `source: 'fallback_vin_decode'`
   - LLM получает инструкции использовать только известные факты, не изобретать

3. **Качество не падает**:
   - FACT-SHEET всегда создается
   - Промпт-контракт всегда применяется
   - LLM получает строгие правила независимо от источника данных

### Строгая валидация качества перед обучением

Обучение включается **ТОЛЬКО** если статья проходит все проверки на 100%:

**Проверки качества:**
- ✅ Quality score >= 95% (0.95)
- ✅ Word count >= 2000 слов
- ✅ Хорошая структура статьи
- ✅ Экспертный тон
- ✅ Практические советы
- ✅ Семантическое покрытие
- ✅ Нет обрывов и незавершенных предложений
- ✅ Все обязательные блоки присутствуют
- ✅ Все блоки прошли валидацию (status: 'VALID')

**Если хотя бы одна проверка не пройдена:**
- Обучение **НЕ применяется**
- Статья сохраняется с меткой `trainingApplied: false`
- В логах указывается причина пропуска обучения

**Результат:** Обучение включается только когда на сайте все на 100% отлично по всем параметрам.
